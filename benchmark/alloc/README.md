# Замеры распределителя памяти

Стенд сличает наш распределитель `awh::alloc` с системным.

## Как гонять

```sh
benchmark/alloc/stand.sh [корень дерева]
```

Библиотека при этом НЕ собирается: стенд берёт исходники модуля напрямую, оттого
годится и на отладочных стендах, где полная сборка занимает десятки минут.

Переменные окружения: `CXX` — собиратель (по умолчанию `c++`), `FLAGS` — добавочные
ключи сборки.

## Устройство

Из одного исходника `stand.cpp` собираются ДВЕ программы: с нашим распределителем и с
системным (`-DAWH_BENCH_SYSTEM`). Разница между ними одна — какой распределитель
обслуживает выдачу; ключи сборки у обеих совпадают дословно, включая
`-fno-builtin-malloc`.

## Соперники — только из подмодулей AWH

Третьей и четвёртой программами идут соперники: **jemalloc** (`submodules/jemalloc`) и
**tcmalloc** (`submodules/gperftools`, часть minimal). Собираются они из подмодулей
дерева — тех же, что лежат рядом с зависимостями самого AWH, — а НЕ берутся из системы:
системная библиотека есть чужая сборка (иная версия, иные ключи), и сличение с нею
мерило бы вдобавок разницу сборок.

- Собирается КОПИЯ подмодуля в каталоге стенда; сам подмодуль остаётся нетронутым.
- Заплаты переноса берутся из `sh/patches/<имя>` и ложатся на копию. У gperftools это
  ветвь строки кэша для Эльбруса (e2k), без неё — `#error`.
- Связывание — статической библиотекой по полному пути и целиком, так что подмена
  соперника системной исключена устройством.
- Соперник обязан ДОКАЗАТЬ обслуживание выдачи приростом собственного учёта; иначе
  он пропускается с отчётом.
- Подмодуль не выложен (`git submodule update --init submodules/jemalloc
  submodules/gperftools`) или не собрался — соперник пропускается с отчётом, без
  всякой подмены.

Нужны: GNU make (`gmake` у BSD) и `autoconf` для jemalloc, `cmake` для gperftools.
autoconf не нужен, если в подмодуле уже лежит порождённый `configure`. Так стенд
возят по машинам поклажей (копия подмодуля с готовым `configure` и файлом `VERSION`),
потому что autoconf стоит не на всех стендах.

Семь сценариев: блоки одного разряда, блоки изменчивого размера, крупные блоки,
удержание множества блоков с освобождением вразбивку, рост перевыдачей, нагрузка
потоками по числу ядер и освобождение блока ЧУЖИМ потоком. Наружу идёт лучший из пяти
заходов.

Сценарий, не сделавший ни одного действия, печатает `НЕДЕЙСТВИТЕЛЬНО`, а не ноль:
показатель вида «на одно действие» при нуле действий укладывается в любой порог с
верхней границей, и молчащий сценарий выходил бы зелёным.
