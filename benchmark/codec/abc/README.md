# Замеры бинарного контейнера ABC

Отчёт по набору сценариев `benchmark/codec/abc`. Меряется модуль `src/codec/abc` —
потоковое чтение записи, сборка записи значение за значением, дерево документа,
владеющее значение и сам контейнер: кадры со сжатием и шифрованием, выборка записи по
номеру и правка на месте.

Набор этот меряет **нас самих во времени** и стережёт регрессии. Сличение с чужими
реализациями двоичной записи ведётся отдельным набором — `tools/benchmark/abc`.

## Как запускать

```sh
# все сценарии подмодуля с проверкой порогов
./benchmarks/codec --filter=abc

# измерение без проверки порогов (калибровка на новой машине)
./benchmarks/codec --filter=abc --relaxed

# один сценарий, отбор ведётся по вхождению в название
./benchmarks/codec --filter="abc: выборка"
```

Отклонение любого показателя от порога завершает прогон с ненулевым кодом, поэтому набор
пригоден как шаг сборки: регрессия останавливает конвейер.

**Замеры в отладочной сборке негодны**: она равномерно медленнее в девять раз и
изображает точечную регрессию там, где её нет.

## Что измеряется и почему именно это

| Сценарий | Что нагружает |
|---|---|
| `чтение ответа службы` | Постоянные издержки на запись: сброс состояния, заведение вместилищ. Запись малая, около сотни октетов, — тот самый случай, ради которого контейнер и написан |
| `чтение крупной записи` | Установившаяся пропускная способность за пределами кэша процессора: 16 МБ отображений, строк и чисел |
| `чтение чисел` | Разбор чисел всех видов: целые обеих знаковостей, дробные и крупные целые |
| `чтение строк` | Содержимое строк вместе с проверкой их на соответствие кодировке |
| `чтение двоичных значений` | Двоичное значение — то, ради чего двоичный контейнер и берут: перекодировки оно не требует и ложится как есть |
| `чтение вложенности` | Стек открытых вместимых: половина записи такого вида приходится на строение, а не на содержимое |
| `выделения на чтение` | Сохранность памяти между записями: буфер разбора и очередь событий разбор переживают, и расход на запись обязан оставаться постоянным |
| `просадка от подачи кусками` | Главное обещание чтения: выдача от нарезки записи не зависит, а стоимость её зависеть почти не должна |
| `задержка чтения ответа службы` | Тот же ответ службы, но мерою времени на запись: на малой записи постоянные издержки в мегабайтах в секунду растворяются |
| `сборка крупной записи` | Сборка исходящей записи значение за значением без удержания дерева |
| `сборка строк` | Укладка строк вместе с проверкой их на соответствие кодировке |
| `выделения на сборку` | Расход на собранную запись: сборка ведёт запись одним вместилищем, растущим удвоением |
| `выигрыш от укладки ссылкой` | **Устройство, а не скорость.** Содержимое сверх порога в запись не копируется вовсе, и выигрыш ниже единицы означал бы, что копия всё-таки делается |
| `задержка сборки ответа службы` | Постоянные издержки на сборку малой записи |
| `сборка дерева крупной записи` | Установившаяся скорость сборки дерева сплошным перечнем узлов |
| `обход собранного дерева` | Обход первым значением вместе с переходом к соседу: переход стоит одного сложения. Дерево собирается до замера, чтобы сборка и обход не скрывали друг друга |
| `перезапись дерева` | Обратная запись собранного дерева |
| `выделения на сборку дерева` | Дерево хранится сплошным перечнем узлов, содержимое — одним хранилищем: расход обязан оставаться считанными единицами |
| `снятие владеющего значения` | **Цена владения.** Дерево обходится считанными выделениями на запись, а владеющее значение держит память у всякого узла: показатель стережёт устройство, а не малость расхода |
| `задержка сборки дерева ответа службы` | Постоянные издержки на сборку дерева малой записи |
| `сборка контейнера без сжатия` | Кадрирование записей вместе с оглавлением, без сжатия и шифрования |
| `сборка контейнера со сжатием` | То же самое со сжатием кадров |
| `сборка контейнера с шифрованием` | То же самое со сжатием и шифрованием кадров |
| `сжатие содержимого контейнера` | **Устройство, а не скорость.** Отношение около единицы означало бы, что кадры уходят на носитель как есть — скажем, оттого что модуль сжатия отвалился молча |
| `выборка записи по номеру` | Выборка ведётся оглавлением и читает лишь тот кадр, где запись лежит. Записи выбираются вразнобой, а не подряд: соседние попадали бы в один и тот же кадр, а кадр выборщиком удерживается |
| `правка контейнера на месте` | Дописывание записи вместе с фиксацией: фиксация переписывает оглавление и заголовки, а прежние кадры оставляет на месте |

Возможностей четырёх последних сценариев у сличаемых реализаций двоичной записи нет
вовсе, и сличать их не с чем: набор стережёт их от собственных регрессий.

## Пороги

Пороги размечены 21.08.2026 по **дну каждого сценария в отдельности**, снятому обходом
двенадцати стендов тремя прогонами отдельными процессами, с двукратным запасом. «Самой
медленной машины» не существует: у ABC дно держит OpenBSD у большинства сценариев,
расход выделений — Ubuntu, обход владеющего значения — DragonFly, просадку от подачи
кусками — NetBSD, выигрыш от укладки ссылкой — ALT.

Прежняя разметка — «по рабочей машине с запасом вчетверо-впятеро» — сторожила мало:
обход собранного дерева стоял при пороге 100 против дна 334, а расход выделений на
снятие значения — при 128 против дна 25.

Правились не все пороги, а лишь те, где поправка существенна. Ужесточение мельче
четверти не берётся: одна и та же машина между двумя обходами даёт до шестой части
расхождения на неизменном коде, и поправка в проценты есть удача съёма, а не сведения о
коде. Порог, подтянутый под неё, откажет при следующем обходе.

Отношению «выигрыш от укладки ссылкой» порог прежде стоял впритык по доводу, что
отношения от машины не зависят. Довод неверен: быстродействие отношение сокращает, а
устройство кучи и цену выделения — нет. Дно 21.5 держит ALT, порог взят вдвое ниже.

### Дно по стендам, 23.08.2026

Карта снята по **двенадцати системам** amd64/x86-64 — FreeBSD, NetBSD, OpenBSD,
DragonFly, Solaris 11.4, OpenIndiana, Alpine (musl), Debian, Fedora, Ubuntu,
OpenSuse, Alt Linux, — отдельным стендом, прогоном **по одной машине за раз**.

Три первых порога **ослаблены** этою картой: прежние 2.50, 12.00 и 93.00 давали
запас 1.06—1.09 при разбросе самой машины ±1 %, и покраснели бы у Solaris на всякой
правке разбора, медленнее на пять сотых, — не будучи регрессией нигде более.

**Замеры гонять по одной машине за раз.** Стенды сидят на одном сервере: прогон
двенадцати разом уронил «чтение двоичных значений» у Solaris с 102—104 до 90—92,
то есть НИЖЕ прежнего порога. Расхождение это было свойством способа измерения, а
не системы: три одиночных прогона дали 102.55, 104.07, 104.39.

**Направление порога по единице измерения не определяется.** «Раз» бывает и
выигрышем (пропуск груза), и просадкой (подача кусками); мкс/зап. и выд./зап. —
чем меньше, тем лучше. Считая запас по карте, направление брать из самих данных:
где все двенадцать машин по одну сторону порога, та сторона и годная.
