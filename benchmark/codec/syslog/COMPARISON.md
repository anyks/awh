# Сравнение кодека SysLog с прежним модулем ANYKS

Отчёт по прогону одних и тех же записей через две реализации разбора сообщений
системного журнала на одной машине, одним собирателем, с одинаковой работой
потребителя.

Собственный отчёт набора — [README.md](README.md); здесь измеряется не сам
разбор, а его место рядом с тем, что было.

## Что с чем сравнивается

| Реализация | Разбор | Дерево | Зависимости |
|---|---|---|---|
| **прежний ANYKS syslog** | целиком, регулярными выражениями | RapidJSON | PCRE2, RapidJSON |
| **AWH `codec::syslog`** | потоковый и целиком | `abc::value_t` | нет |

Прежний модуль — тот самый, что владелец дал для аналогии
(`/Users/forman/Work/GIT/anyks/syslog`). Иных разборщиков системного журнала на
C++ в открытом виде нет: описания эти разбирают либо сами сборщики журналов
(`syslog-ng`, `rsyslog` — разбор там вплетён в приём и в правила отбора и
отдельно не мерится), либо связки на Python и Go, и мерить их рядом было бы
сличением языков, а не разборов.

## Поверка равенства работы

**Числа без этой поверки не значат ничего.** Прежде замера доказано, что обе
реализации на одних записях делают одно и то же.

### Запись RFC 5424

```
<165>1 2023-04-11T23:29:33.003Z mymachine.example.com evntslog 1093 ID47
[exampleSDID@32473 iut="3" eventSource="Application" eventID="1011"]
An application event log entry with a reasonably long free-form message body
```

| Что спрошено | прежний ANYKS syslog | AWH `codec::syslog` |
|---|---|---|
| описание | RFC 5424 | RFC 5424 |
| источник | 20 | 20 |
| важность | 5 | 5 |
| имя узла | `mymachine.example.com` | `mymachine.example.com` |
| приложение | `evntslog` | `evntslog` |
| опознаватель работы | `1093` | `1093` |
| опознаватель сообщения | `ID47` | `ID47` |
| текст сообщения | совпадает знак в знак | совпадает знак в знак |
| поле `iut` | `3` | `3` |
| поле `eventID` | `1011` | `1011` |
| дата | `2023-04-11 23:29:33` | `2023-04-12 02:29:33` |

### Запись RFC 3164

```
<45>Oct 22 12:34:56 freebsd-log.dmz.example.org syslog-ng[8763]:
[notice]syslog-ng starting up; version='4.7.1', ...
```

| Что спрошено | прежний ANYKS syslog | AWH `codec::syslog` |
|---|---|---|
| описание | RFC 3164 | RFC 3164 |
| источник | 5 | 5 |
| важность | 5 | 5 |
| имя узла | `freebsd-log.dmz.example.org` | `freebsd-log.dmz.example.org` |
| приложение | `syslog-ng` | `syslog-ng` |
| опознаватель работы | `8763` | `8763` |
| текст сообщения | совпадает знак в знак | совпадает знак в знак |

Все поля совпали, кроме одного — даты, и расхождение это разобрано ниже.

### Про расхождение даты

Прежний модуль выдаёт дату **зоной, в записи стоящей** (`Z`, то есть UTC), AWH —
**местной зоной машины**. Момент времени у обоих один и тот же: 23:29:33 UTC есть
02:29:33 по московскому времени. Разница в том, каким временем выдаётся
представление, а не в том, что разобрано.

Выбор AWH последователен с разбором: даты, зоны не несущие (а вид RFC 3164 её не
несёт вовсе), разбираются местным временем — иначе журнал соседней машины
съезжал бы на величину её зоны. Выдавать одни даты местным временем, а другие
зоной записи значило бы отдавать потребителю два разных мерила под одним именем.

Сама зона отправителя при этом **не теряется**: дерево держит дату тем видом,
каким она стояла в записи, и кодек её не переписывает вовсе — что закреплено
проверкой `CodecSysLogWriter.DateIsNeverRewritten`. Приведение даты к
нужному виду есть дело потребителя, и ход `timestamp` события ему для того и дан.

## Показатели

Записи — те же, на каких доказано равенство работы. Лучшее из шести прогонов
отдельными процессами, macOS ARM64, Release, 07.09.2026.

### Запись RFC 5424 (218 октетов)

| Реализация | Пропускная способность | Отношение |
|---|---|---|
| прежний ANYKS syslog → RapidJSON | 2.96 МБ/с | — |
| **AWH `document_t`** → `abc::value_t` | **58.43 МБ/с** | **19.7×** |
| **AWH `reader_t`** (потоковое чтение) | **334.09 МБ/с** | **112.9×** |

### Запись RFC 3164 (219 октетов)

| Реализация | Пропускная способность | Отношение |
|---|---|---|
| прежний ANYKS syslog → RapidJSON | 3.20 МБ/с | — |
| **AWH `document_t`** → `abc::value_t` | **96.25 МБ/с** | **30.1×** |
| **AWH `reader_t`** (потоковое чтение) | **586.84 МБ/с** | **183.4×** |

Сличаются **сопоставимые работы**: `document_t` и прежний модуль оба укладывают
разбор в дерево, и строка `дерево к дереву` — честная. Строка потокового чтения
дана отдельно, ибо работа там иная: событий в дерево оно не кладёт вовсе, и
ставить её рядом как «во столько же раз быстрее» было бы подменой предмета.

### Откуда разница

Три источника, по убыванию веса:

1. **Регулярные выражения против прямого разбора.** Прежний модуль разбирает
   запись выражениями PCRE2: всякое поле — своё выражение, а сама запись
   проходится по многу раз. Кодек AWH идёт по записи один раз, отделяя поля
   счётом слов и границами знаков.
2. **RapidJSON против `abc::value_t`.** Прежнее дерево строится сборкой
   документа JSON; кодек кладёт значения прямо в узлы дерева контейнера ABC.
3. **Копирование.** Потоковое чтение AWH содержимое **само не копирует**: события
   выдают представления во внутреннее хранилище разбора. Оттого строка `reader_t`
   и оторвалась от прочих настолько.

### Отчего разница на RFC 3164 больше

Запись устаревшего описания разбирается кодеком быстрее записи RFC 5424 (587
против 334 МБ/с), а прежним модулем — почти так же (3.20 против 2.96). У кодека
на RFC 3164 нет ни разбора блоков структурированных данных, ни снятия отмены
знаков; у прежнего модуля стоимость определяется числом прогонов выражений по
записи, а оно у обоих описаний схоже.

## Чего сличение НЕ показывает

* **Стенды, кроме одной машины.** Числа сняты на macOS ARM64. Показатель
  пропускной способности от машины **зависит**, и на прочих стендах отношения
  будут иными — сохранится порядок, но не множитель.
* **Расход памяти прежнего модуля.** Счётчик выделений AWH видит только свою
  замену оператора; RapidJSON и PCRE2 держат свои распределители, и сличать
  расход было бы сличением учётов, а не расходов.
* **Работу сборщика журналов целиком.** Меряется разбор одной записи, а не приём
  из сети, отбор по правилам и запись в хранилище.
