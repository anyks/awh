# Бенчмарки контейнера JSON

Отчёт по набору сценариев `benchmark/codec/json`. Измеряется модуль
`src/codec/json` — потоковое чтение текста, сборка дерева, обход дерева,
перезапись дерева в текст и запись текста значение за значением.

Набор этот меряет **нас самих во времени** и стережёт регрессии. Сличение с
чужими разборщиками ведётся отдельным набором — `tools/benchmark/json`, а
соответствие стандарту — `tools/verify/codec/json`.

## Как запускать

```sh
# все сценарии подмодуля с проверкой порогов
./benchmarks/codec --filter=json

# измерение без проверки порогов (калибровка на новой машине)
./benchmarks/codec --filter=json --relaxed

# один сценарий, отбор ведётся по вхождению в название
./benchmarks/codec --filter="выделения"
```

Отклонение любого показателя от порога завершает прогон с ненулевым кодом,
поэтому набор пригоден как шаг сборки: регрессия останавливает конвейер.

## Что измеряется и почему именно это

| Сценарий | Что нагружает |
|---|---|
| `чтение ответа службы` | Постоянные накладные расходы на документ: сброс состояния, заведение вместилищ, определение кодировки. Документ малый, около 250 октетов, — тот самый случай, ради которого контейнер и написан |
| `чтение описания настроек` | Настройки службы в несколько килобайт: вложенные объекты и массивы, разбираемые однажды при запуске |
| `чтение крупного документа` | Установившаяся пропускная способность за пределами кэша процессора: 16 МБ объектов, массивов, строк и чисел в соотношении настоящих выгрузок |
| `чтение чисел` | Определение самого узкого вмещающего вида числа вместе с преобразованием записи. Виды чередуются: целое без знака, целое со знаком, дробное, дробное с порядком |
| `чтение строк` | Содержимое строк: английский текст, неанглийский текст и отменяющие последовательности разбираются тремя разными путями |
| `чтение вложенности` | Стек открытых вместилищ и размах поддерева: половина знаков такого документа приходится на строение, а не на содержимое |
| `просадка от подачи кусками` | Главное обещание чтения: выдача от нарезки текста не зависит, а стоимость её зависеть почти не должна. Подача кусками по семь байтов рвёт всякое значение |
| `выделения на чтение` | Сохранность памяти между документами: хранилище знаков и очередь событий разбор переживают, и расход на документ обязан оставаться постоянным |
| `задержка чтения ответа службы` | Тот же ответ службы, но мерою времени на документ: на мелком документе постоянные издержки в мегабайтах в секунду растворяются |
| `запись ответа службы` | Сборка исходящего документа значение за значением без удержания дерева |
| `запись чисел` | Устройство записи числа: кратчайшая запись вычисляется разбором чисел сразу, без подбора точности пробами с обратным чтением |
| `запись отменяемых знаков` | Отмена кавычек, знака отмены, перевода строки и управляющих знаков |
| `запись человекочитаемым видом` | Отступы и переводы строк: вид переключается настройкой, и собирающий документ код от него не зависит |
| `выделения на запись` | Расход на собранный и отданный наружу документ. Замер ведётся вместе с изъятием текста: без изъятия расход нулевой, ибо сброс записи память удерживает |
| `сборка дерева ответа службы` | Заведение вместилищ дерева на мелком документе |
| `сборка дерева крупного документа` | Установившаяся скорость сборки дерева сплошным перечнем узлов |
| `сборка дерева чисел` | Сборка дерева там, где всякий узел требует определения вида числа |
| `обход собранного дерева` | Обход ссылками: переход к соседу и пропуск вложенного вместилища стоят одного сложения. Дерево собирается до замера, чтобы сборка и обход не скрывали друг друга |
| `перезапись дерева в текст` | Обратная запись собранного дерева |
| `задержка обращения по имени поля` | Устройство обращения по имени: мелкие объекты разыскиваются перебором детей, крупные — отображением, заводимым по требованию |
| `выделения на сборку дерева` | Дерево хранится сплошным перечнем узлов, знаки — одним хранилищем: расход обязан оставаться считанными единицами |
| `выигрыш от переиспользования документа` | Сохранность памяти между разборами: потребителю, разбирающему много документов подряд, надлежит держать один объект документа |
| `снятие значения с дерева` | Мост от разбора к владению на крупном документе: снятие поддерева собственной памятью |
| `снятие значения ответа службы` | Тот же мост на мелком документе, где решают постоянные издержки |
| `потоковая сборка значения` | Сборка документа полем за полем без дерева вовсе — путь потребителя, строящего исходящий документ |
| `запись значения в текст` | Обратная запись владеющего значения |
| `обход владеющего значения` | Обход россыпью вместилищ, сличаемый с обходом дерева ссылками |
| `выделения на снятие значения` | **Цена владения.** Дерево обходится одним выделением на документ, а значение держит память у всякого узла: показатель стережёт устройство, а не малость расхода |

## Пороги

Пороги назначены по наименьшему из показателей отладочных стендов с двукратным
запасом: время на занятой машине расходится между прогонами на десятки
процентов, и порог, заданный впритык, поднимал бы ложную тревогу чаще, чем
ловил бы настоящую регрессию.

**Калибровать пороги по рабочей машине нельзя**: между нею и самым медленным из
стендов разница пятикратная.

## Показатель «не более» при молчащем счётчике

Сценарии расхода памяти проверяют работоспособность учёта прежде самого
показателя: нулевой расход меньше всякого порога, и молчащий счётчик
отчитывался бы «уложился» всегда. Поломка эта уже случалась у соседнего
контейнера — у MinGW стандартная библиотека подключалась отдельной библиотекой,
и выделения внутри неё замене оператора в приложении видны не были.
