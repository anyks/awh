# Щупы для стендов без полной сборки библиотеки

Щупы эти нужны там, где собрать библиотеку целиком дорого или нечем, а проверить
платформенную ветвь всё же надо. Полноценный набор проверок они НЕ заменяют — они
закрывают ровно тот слой, что назван в заголовке щупа.

## abc-storage

Файловый слой хранилища ABC: заведение файла, запись и чтение со смещением, длина,
отказы. Проверяет ветвь `#if _WIN32 || _WIN64` в `src/codec/abc/storage.cpp`, где вместо
`fseeko`/`ftello` зовутся `_fseeki64`/`_ftelli64`.

Собирается двумя файлами:

```
g++ -std=c++17 -O1 -I include src/codec/abc/storage.cpp tools/probe/abc-storage.cpp -o abc-storage
```

**У Windows звать собиратель `/mingw64/bin/g++` ПОЛНЫМ путём.** По ssh в путь первым
встаёт `/usr/bin/g++`, а это собиратель окружения MSYS с целью `x86_64-pc-cygwin`: он
`_WIN32` не объявляет вовсе, берёт ветвь POSIX и валится на необъявленном `fseeko`. Отказ
этот — свойство окружения, а не дефект модуля.

Чего щуп НЕ проверяет: работы `bind` и `load`. Они уводят в правку и разбор кадров, а те
тянут за собой сжатие и шифрование — ради них пришлось бы собирать библиотеку целиком.
Опоры этих двух работ в щупе заведены пустыми, лишь бы прошло связывание.

Прогон 19.08.2026: macOS ARM64 — 19 из 19, Windows x86-64 MinGW64 (gcc 15.3) — 19 из 19.

## epoll-enospc

Переходная ветвь согласования подписки у движка `epoll`. Ядро отвергает
`epoll_ctl(ADD)` с `ENOSPC`, когда исчерпан предел наблюдений пользователя. Отказ этот
**временный**: предел отпускается вместе с чужими подписками, — и движок обязан оставить
дескриптор в очереди согласования и подать подписку заново, а не похоронить событие.
Проверяет ветвь в `src/net/backend/gnu/epoll.cpp`.

Щуп опускает `/proc/sys/fs/epoll/max_user_watches` до единицы, поднимает пару событий TCP
по петле, крутит опрос, затем возвращает предел и ждёт доставки сообщения. Предел
возвращается и при всяком исходе, включая отказ.

В отличие от `abc-storage`, этот щуп **требует собранной библиотеки**: он поднимает движок
целиком, и меньшим слоем ветвь эту не достать.

```
g++ -std=c++20 -I include -I contrib/include tools/probe/epoll-enospc.cpp -o epoll-enospc \
    build/libawh.a third_party/lib/libdependence.a -lsctp -lpthread
```

Звать от надзорного: без прав настройка ядра не правится, и щуп отступает, а не лжёт.
Доводы: `epoll-enospc [порт] [оборот возврата предела]`.

**Годность щупа доказывается вторым прогоном, а не первым.** Доставка сама по себе ничего
не значит: она случилась бы и тогда, когда `ENOSPC` не наступал вовсе. Оттого прогонять
надо ДВАЖДЫ - обычно и с оборотом возврата заведомо бо́льшим числа оборотов опроса
(например 999), отчего предел не возвращается вовсе:

```
epoll-enospc                → доставлено=ДА
epoll-enospc 43919 999      → доставлено=НЕТ
```

Оба исхода вместе и означают, что щуп упирается именно в предел наблюдений. Один лишь
первый прогон - печатающая проверка, какая пройдёт и при молчащем движке.

Прогон 23.08.2026: Debian 12 (ядро 6.1) — ДА/НЕТ, Alpine 3.24 (ядро 6.18) — ДА/НЕТ.
