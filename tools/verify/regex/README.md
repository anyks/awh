# Стенды сверки модуля регулярных выражений

Модуль `awh::regex` поддерживает тот же набор синтаксиса и выводит те же границы
совпадения, что и PCRE2. Стенды этого каталога проверяют это утверждение сличением
с эталонной реализацией.

## Зачем эталон вынесен из поставки

PCRE2 в поставку библиотеки не входит и её сборке не требуется. Эталон остаётся
подмодулем и собирается местно единственно ради сверки: набор синтаксиса и границы
совпадения обязаны отвечать эталону и впредь, а проверить это без него нельзя.

Расхождения, выбранные осознанно, описаны разделами «Намеренные решения» в
заголовочных файлах модуля. Разбиение на графемные кластеры следует действующей
редакции приложения UAX #29 стандарта Юникода, тогда как таблица разбиения PCRE2
отстаёт от неё в трёх правилах — это единственное известное расхождение.

Что расхождение ограничено набором правил, а таблиц не касается, устанавливают два
отдельных стенда: `grapheme_tables` применяет правила разбиения эталона к таблицам
модуля и сличает вывод с эталоном, а `grapheme_rules` сличает разбиение модуля
с правилами стандарта. Оба обязаны показывать ноль расхождений, тогда как прямое
сличение `grapheme` показывает расхождения ровно тех трёх правил.

## Сборка и запуск

```
./tools/verify/regex/build.sh [каталог сборки] [каталог эталона]
```

По умолчанию стенды собираются в `/tmp/verify-regex`, а эталон — в его подкаталоге
`pcre2`. Эталон собирается однажды и переиспользуется при последующих запусках.
Исходные тексты эталона получаются подмодулем:

```
git submodule update --init submodules/pcre2
```

Стенды собираются из исходных текстов модуля напрямую, минуя библиотеку: сверка
обязана проверять текущее состояние исходных текстов, а не состояние библиотеки,
собранной когда-то ранее.

Стенд `properties` читает набор имён свойств `sh/unicode.accepted` и запускается
из корня репозитория либо принимает путь набора первым доводом.

Каждый стенд выводит количество сличений и количество расхождений, а при наличии
расхождения — первое из них. Код возврата, отличный от нуля, означает расхождение.

## Состав стендов

| Стенд | Что сличается |
|---|---|
| `corpus` | Границы совпадения и захваченных групп на наборе выражений |
| `syntax` | Приём и отклонение выражений на порождённых текстах |
| `automaton_verdict` | Вердикт наличия совпадения детерминированного исполнения |
| `reverse` | Позиция начала совпадения, найденная проходом в обратном направлении |
| `backtrack` | Границы совпадения выражений нерегулярного подмножества |
| `long` | Границы совпадения на текстах большой длины |
| `word` | Привязка к границе слова во всех сочетаниях соседних символов |
| `classes` | Сокращённые классы символов по всем кодовым значениям |
| `properties` | Свойства Юникода по всем кодовым значениям |
| `grapheme` | Разбиение на графемные кластеры |
| `grapheme_tables` | Правила разбиения эталона на таблицах модуля против эталона |
| `grapheme_rules` | Правила разбиения стандарта против разбиения модуля |
| `caseless` | Сопоставление без учёта регистра по всем кодовым значениям |
| `names` | Виды записи именованных групп, ссылок на них и вызовов по имени |
| `byname` | Выборка захваченного текста по имени группы, включая одноимённые |
| `static` | Приём выражений и количество захватывающих групп |
| `matching` | Границы совпадения исполнения без возврата |
| `automaton` | Вердикт детерминированного исполнения на привязках к позиции |
| `engine` | Границы совпадения движка на текстах различной длины |

Стенды `static`, `matching`, `automaton` и `engine` собираются вместе с тестовым
окружением проекта и требуют библиотеки GoogleTest.
