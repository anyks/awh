# Сличение разбора JSON с эталоном

Стенд сличает разбор документов модулем `awh::codec::json` с двумя независимыми
основаниями:

* **JSONTestSuite** — общепризнанное собрание из 318 текстов, где для всякого известно,
  обязан ли разбор принять его (`y_`), отвергнуть (`n_`) либо волен решать сам (`i_`);
* **модуль `json` языка Python** — перезапись принятого дерева обязана читаться тем же
  самым значением, что и исходный текст.

Проверяется вдобавок независимость выдачи от нарезки: всякий текст разбирается при подаче
целиком и кусками по 1, 2, 3 и 7 байтов, и исход обязан совпадать при всякой нарезке.

Сличение это закрывает то, чего не закрывают ни набор проверок, ни ворошитель:
**соответствие стандарту**. Ворошитель сличает нас с нами же — он ловит расхождения между
способами подачи и порчу памяти, но если мы неверно понимаем стандарт, он ошибётся вместе
с нами.

## Запуск

```sh
./tools/verify/codec/json/build.sh
/tmp/verify-json/verify /tmp/verify-json/corpus > /tmp/verify-json/dump.tsv
python3 tools/verify/codec/json/compare.py /tmp/verify-json/dump.tsv /tmp/verify-json/corpus
```

Корпус забирается сборкой единожды. Стенд возвращает ненулевой код при обнаружении хотя бы
одного расхождения.

Тем же порядком прогоняется набор преобразований, где сличается уже не исход разбора, а
точность чисел и обращение с повторяющимися именами полей:

```sh
/tmp/verify-json/verify /tmp/verify-json/transform > /tmp/verify-json/transform.tsv
python3 tools/verify/codec/json/compare.py /tmp/verify-json/transform.tsv /tmp/verify-json/transform
```

## Итог прогона

| основание | текстов | исход |
|---|---:|---|
| обязаны приниматься (`y_`) | 95 | приняты все |
| обязаны отвергаться (`n_`) | 188 | отвергнуты все |
| отданы на усмотрение (`i_`) | 35 | принято 13, отвергнуто 22 |
| согласие значений с эталоном | 316 | расхождений нет |
| независимость от нарезки | 318 | расхождений нет |
| набор преобразований | 22 | расхождений нет |

Два текста сличению значений не поддаются, ибо **эталон способнее нас не был**: сам Python
их отвергает, а мы принимаем — это `i_string_UTF-16LE_with_BOM.json` и
`i_structure_UTF-8_BOM_empty_object.json`. Кодировку мы опознаём по метке порядка байтов и
разбираем, тогда как модуль `json` языка Python отвергает и метку UTF-8, и текст в UTF-16.

## Ослабление правил при сличении

Разбор ведётся с правилом `duplicate_t::KEEP`: стандарт повторяющихся имён полей объекта не
запрещает, а наше правило по умолчанию их отвергает. Сличение идёт со стандартом, оттого
правило здесь ослаблено намеренно.

## Что найдено сличением

**Дробное записывалось целым.** Число `1.0` кратчайшей записью выходило как `1`, то есть
перезапись меняла вид значения: потребитель собранного текста видел целое там, где было
дробное. Обнаружено набором преобразований (`number_1.0.json`), исправлено — дробное
записывается дробным всегда.
