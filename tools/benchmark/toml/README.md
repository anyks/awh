# Стенды сравнения контейнера TOML

Стенды сличения разбора текста настроек TOML: контейнер AWH против четырёх
свободных реализаций языка C и C++. Отчёт по прогону —
[benchmark/codec/toml/COMPARISON.md](../../../benchmark/codec/toml/COMPARISON.md).

## Как получить и собрать

Исходные тексты сравниваемых реализаций в репозиторий не входят и получаются
оснасткой в `third_party/rival/toml`.

```sh
# получение исходных текстов сравниваемых реализаций
./tools/benchmark/toml/fetch.sh

# сборка библиотеки AWH с оптимизацией, если она ещё не собрана
cmake -B build-release -DCMAKE_BUILD_TYPE=Release . && make -C build-release awh

# сборка всех шести стендов
./tools/benchmark/toml/build.sh
```

Сторона AWH собирается **обязательно с оптимизацией**: сборка репозитория по
умолчанию идёт без `-O` и с инструментированием покрытия, и сравнивать её с
чужими реализациями нельзя. Стенды собираются одним компилятором с одними
флагами `-O3 -DNDEBUG` и складываются в `/tmp/rival-toml`.

## Как запускать

```sh
# все сценарии одного стенда
/tmp/rival-toml/awh

# один сценарий
/tmp/rival-toml/awh --filter=large

# проверка равенства выполненной работы
/tmp/rival-toml/awh --checksum
```

Гонять стенды следует **по очереди на свободной машине**: показатели чувствительны
к загрузке, и прогон двух стендов внахлёст меряет соседа, а не разбор.

## Состав стендов

| Стенд | Реализация | Что представляет |
|---|---|---|
| `awh` | `awh::codec::toml::reader_t` | Потоковое чтение событиями, дерева не строится |
| `awh-tree` | `awh::codec::toml::document_t` | Сборка дерева настроек |
| `tomlplusplus` | [toml++ 3.4.0](https://marzer.github.io/tomlplusplus) | Дерево, C++17, ближайший по устройству соперник |
| `toml11` | [toml11 4.4.0](https://github.com/ToruNiina/toml11) | Дерево, C++11, хранит положение всякого значения в исходном тексте |
| `cpptoml` | [cpptoml](https://github.com/skystrife/cpptoml) | Дерево, C++11 поры TOML 0.5, разбор лишь из потока стандартной библиотеки |
| `tomlc99` | [tomlc99](https://github.com/cktan/tomlc99) | Дерево, C99, разбор правкой самого текста на месте, поиск имени перебором |

Эталонные тексты и количества прогонов **совпадают со сценариями**
`benchmark/codec/toml`: сравниваются реализации разбора, а не разные объёмы
работы. Расхождение хотя бы в одном тексте обесценивает отчёт целиком, поэтому
менять их следует одновременно в обоих местах.

## Чем стенды неизбежно расходятся

Сравнение честно лишь тогда, когда расхождения названы прямо.

**Обход собранного дерева.** Стенд `awh-tree` собранное дерево не обходит:
перебора дочерних имён дерево настроек TOML не предлагает вовсе — обход целиком
выполняется потоковым чтением, а дерево отвечает на запрос по имени. Стенд потому
меряет одну лишь сборку дерева, тогда как сличаемые реализации обход оплачивают.
Работу, равную обходу, выполняет стенд `awh`, и сличать с ними по совести следует
его. Контрольную сумму `awh-tree` по той же причине не выдаёт.

**Подача текста.** `awh`, `awh-tree`, `toml++` и `toml11` разбирают текст прямо из
памяти. `cpptoml` подачи из памяти не предлагает вовсе — стенд собирает
`std::istringstream` со своей копией текста на всякий прогон. `tomlc99` разбирает
лишь изменяемую последовательность знаков, правя её на месте, — изменяемая копия
собирается тоже на всякий прогон. Это не помеха замеру, а часть цены решения
работать с потоком либо с правкой на месте, и обойти её потребитель не может тоже.

**Примечания.** У `awh` выдача примечаний и пустых строк событиями **отключена**:
сличаемые реализации не выдают ни того, ни другого, и оставлять её включённой
значило бы сравнивать разный объём работы. Чего стоят примечания событиями,
показывает набор `benchmark/codec/toml` — там они включены.

**Строгость.** `cpptoml` писан по описанию TOML 0.5 и часть построений, ныне
запрещённых, принимает. Столбец его следует читать как «скорость на таком тексте»,
а не как «умение прочесть его правильно».

## Про равенство выполненной работы

Каждый стенд обязан прочитать имя таблицы, имя ключа и значение: без этого часть
реализаций работу по их выдаче не выполнит вовсе — `tomlc99`, к примеру, удерживает
строковое значение дословно и снимает ограду лишь при чтении, — а компилятор вправе
устранить измеряемый разбор целиком. Строковые значения складываются в контрольную
сумму, имена — в отдельный приёмник.

```
checksum 26469037785 entries 26672649
```

Числа, логические значения и отметки времени в сумму не входят намеренно:
реализации выдают их разными типами языка, и складывать их в одну сумму значило бы
объявить расхождением разницу представлений, а не разный объём работы. Количество
прочитанных пар при этом учитывается для всех значений без изъятия, и **совпадать
оно обязано до единицы**: расхождение в нём означает, что стенды прочли разное.
