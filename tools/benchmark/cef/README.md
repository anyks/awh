# Стенд сличения кодека CEF

Стенд разбирает **одну и ту же запись** прежним модулем ANYKS и кодеком AWH,
печатая сперва поверку равенства работы, а затем показатели. Отчёт по прогону —
[benchmark/codec/cef/COMPARISON.md](../../../benchmark/codec/cef/COMPARISON.md).

## Почему участник один

Разборщиков CEF на C++ в открытом виде нет: формат разбирают либо надстройки над
сборщиками журналов, либо связки на Python и Java. Сличать их рядом значило бы
мерить языки, а не разборы. Оттого участник один — прежний модуль ANYKS, тот
самый, что дан был для аналогии устройства.

## Поверка равенства работы

Стенд печатает её ДО чисел и не по обычаю, а по необходимости: обе реализации
строят дерево, но итоги их сходятся не во всём. Поверка спрашивает у обеих число
разобранных пар, адрес, число, MAC и метку времени — и расхождения выносит на
свет, вместо того чтобы прятать их за средним значением. Замер, у которого не
доказано, что стороны делают одно и то же, годен лишь на то, чтобы вводить в
заблуждение.

## Сборка и запуск

```sh
./build.sh              # пути задаются LEGACY, PCRE, RAPIDJSON, AWHLIB
./comparison 20000      # число кругов, по умолчанию 20000
```

Прежний модуль требует PCRE2 и RapidJSON: их пути задаются отдельно, ибо в его
дереве подмодули не собраны. Кодек AWH не требует ничего сверх собственной
библиотеки — в том и есть одна из измеряемых разниц.

## Ловушки

**Прогонять на свободной машине.** Показатели идут в отчёт, а соперничество за
ядра даёт просадку, неотличимую от разницы реализаций.

**Брать лучшее из нескольких прогонов процесса.** На Apple Silicon ядра
двумодальны, и середина внутри одного прогона смещена целиком.

**Не менять запись между прогонами.** Запись подобрана так, что все её ключи
словарю известны: ключ `user`, стоявший в образце владельца, описанию CEF не
принадлежит, и строгое сличение отвергает запись с ним законно.
