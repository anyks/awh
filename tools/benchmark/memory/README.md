# Удельный расход памяти на подключение

Четыре программы, замеряющие, во что обходится одно наблюдаемое подключение
движку AWH и трём чужим циклам событий.

## Зачем отдельная оснастка

Полный объём процесса для этого не годится. AWH — платформа: в тот же процесс
слинкованы сжатие, регулярные выражения и TLS, а libev, libevent и libuv суть
циклы событий и ничего этого не несут. Разность их баз измеряет состав
библиотеки, а не работу сетевого движка, и от количества подключений не зависит
вовсе. Сравнение по полному объёму ставит платформе в вину то, чего сетевой
движок не тратил.

Сравнивать можно наклон: объём при большом количестве подключений минус объём
при малом, делённое на разность количеств. База при таком вычитании сокращается
целиком, и остаётся ровно то, что стоит подключение.

## Что делает оснастка

Заводит заданное количество соединённых пар сокетов, подписывает каждый сокет на
готовность к чтению и выводит две величины: количество подключений и пик занятой
памяти в октетах. Обмена нет — подключения только заводятся и остаются
наблюдаемыми.

Одно подключение есть пара сокетов: клиентский и принятый сервером. Оба
наблюдаются, поэтому расход на сокет вдвое меньше расхода на подключение.

## Сборка

```sh
brew install libevent libev libuv

c++ -std=c++17 -O3 -o /tmp/mem-libev tools/benchmark/memory/libev.cpp \
	-I/opt/homebrew/opt/libev/include -L/opt/homebrew/opt/libev/lib -lev

c++ -std=c++17 -O3 -o /tmp/mem-libevent tools/benchmark/memory/libevent.cpp \
	-I/opt/homebrew/opt/libevent/include -L/opt/homebrew/opt/libevent/lib -levent_core

c++ -std=c++17 -O3 -o /tmp/mem-libuv tools/benchmark/memory/libuv.cpp \
	-I/opt/homebrew/opt/libuv/include -L/opt/homebrew/opt/libuv/lib -luv
```

Стенд движка собирается теми же флагами, что и набор бенчмарков, — сравнивать
реализации, собранные с разной оптимизацией, бессмысленно:

```sh
c++ -std=c++17 -O3 -DNDEBUG -DAWH_STATICLIB -D__AWH_USE_TCMALLOC__ \
	-x objective-c++ -fobjc-arc -isystem include \
	-I third_party/include -I third_party/include/tcmalloc -I contrib/include \
	tools/benchmark/memory/awh.cpp -x none -o /tmp/mem-awh \
	build-release/libawh.a third_party/lib/libdependence.a \
	third_party/lib/libtcmalloc_minimal.a third_party/lib/libcommon.a -framework Foundation
```

## Прогон

Каждый прогон занимает вдвое больше дескрипторов, чем указано подключений, и
оставляет их в состоянии `TIME_WAIT`. Предел дескрипторов нужно поднять, а между
прогонами выдержать паузу — иначе следующий не сможет занять порты:

```sh
ulimit -n 20000

for impl in libev libevent libuv awh; do
	for n in 1000 5000; do
		printf "%s " "$impl"; /tmp/mem-$impl $n; sleep 15
	done
done
```

Удельный расход на сокет считается как разность объёмов, делённая на разность
количеств сокетов, то есть на удвоенную разность количеств подключений.

## Результат

Снято на Apple M-series, macOS, `1000` против `5000` подключений:

| Реализация | 1000 подключений | 5000 подключений | На сокет |
|---|---:|---:|---:|
| libev | 1.83 МБ | 2.50 МБ | **88 Б** |
| libevent | 2.02 МБ | 3.84 МБ | **240 Б** |
| libuv | 2.23 МБ | 4.95 МБ | **356 Б** |
| **AWH** | 12.89 МБ | 19.66 МБ | **887 Б** |

Величина объяснена целиком: узел события занимает 872 октета для клиента и 528
для однорангового узла, и 887 октетов на сокет есть их средний вес плюс
накладные аллокатора. Разбор — в
[отчёте о производительности](../../../benchmark/net/io/README.md).
