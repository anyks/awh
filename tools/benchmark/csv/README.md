# Сравнение контейнера CSV со сторонними реализациями

Стенды разбирают одни и те же эталонные таблицы одним и тем же способом и выдают
пропускную способность разбора. Работа, выполненная стендом, сверяется контрольной
суммой: без такой сверки реализация, выдающая поля ссылками и содержимого не читающая,
выглядела бы быстрее прочих, ничего для того не сделав.

## Сравниваемые реализации

| стенд | реализация | устройство |
|---|---|---|
| `awh` | `awh::codec::csv` | потоковое чтение событиями, приведение к UTF-8 |
| `libcsv` | [rgamble/libcsv](https://github.com/rgamble/libcsv) | потоковое чтение обработчиками, язык C |
| `csv-parser` | [vincentlaucsb/csv-parser](https://github.com/vincentlaucsb/csv-parser) | потоковое чтение записями, C++17 |
| `csv2` | [p-ranav/csv2](https://github.com/p-ranav/csv2) | обход отображённого в память текста |
| `fast-cpp` | [ben-strasser/fast-cpp-csv-parser](https://github.com/ben-strasser/fast-cpp-csv-parser) | чтение по строкам, число столбцов задаётся при сборке |
| `rapidcsv` | [d99kris/rapidcsv](https://github.com/d99kris/rapidcsv) | загрузка таблицы целиком |

## Сценарии

| сценарий | размер | содержимое |
|---|---|---|
| `narrow` | 16 МБ | много записей о пяти столбцах, без единой кавычки |
| `wide` | 16 МБ | 32 столбца, работа приходится на разделители |
| `quoted` | 8 МБ | всякое поле в кавычках, внутри разделители и удвоенные кавычки |
| `multiline` | 8 МБ | поля с переводами строк внутри кавычек |
| `small` | 200 байт | таблица размером с ответ службы, 200 000 прогонов |

Сценарий `small` меряет не разбор содержимого, а стоимость заведения самого разбора:
на нём расходятся реализации, заводящие потоки и накопители на всякий разбор.

## Сборка и запуск

```sh
cmake -B build-release -DCMAKE_BUILD_TYPE=Release && make -C build-release awh
./tools/benchmark/csv/build.sh
for STAND in awh libcsv csv-parser rapidcsv fast-cpp csv2; do
	echo "=== $STAND"; /tmp/rival-csv/$STAND
done
```

Ключ `--filter=<название>` отбирает сценарии по вхождению в название, ключ `--checksum`
выводит контрольную сумму прочитанного содержимого, количество полей и записей.

## Что учитывать при прогоне

- Замеры имеют смысл только в сборке `Release`: каталог `build` отладочный, и
  равномерное девятикратное замедление изображает точечную просадку.
- Прогон снимать на свободной машине: под сборкой отказывают проверки по скорости.
- Стенды гонять по очереди, а не разом: они соперничают за память и кэш.
