# Сборка AWH оснасткой Microsoft Visual Studio

Набор этот — самостоятельный двойник `sh/`, а не оболочка над ним. MSYS2 нигде не
участвует: Visual Studio ищется через `vswhere`, CMake и Ninja берутся из её состава,
слияние архивов ведёт `lib.exe`, а подстановку в `FindAWH.cmake` — PowerShell.

## Порядок

```bat
git submodule update --init --recursive
bat\build_third_party.bat
```

Затем обычная сборка CMake, указав `cl` компилятором:

```bat
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=cl -DCMAKE_CXX_COMPILER=cl ..
cmake --build .
```

Проверено на Windows 11 ARM64, Visual Studio 2022 Community, набор средств 14.43.

## Что нужно иметь

| средство | обязательно | зачем |
|---|---|---|
| Visual Studio 2019 и новее, часть «Разработка классических приложений на C++» | да | оснастка |
| `git` | нет | лишь чтобы перевести исходники зависимостей на нужную версию |
| CMake, Ninja | нет | берутся из состава Visual Studio, если своих нет |
| «Средства C++ Clang для Windows» | нет | ускоренные части BoringSSL, см. ниже |

## Что следует знать

**Зависимости лежат отдельно от сборки MinGW** — в `third_party-msvc`. Довод не в
опрятности: часть зависимостей собирает под оснастку и ЗАГОЛОВКИ (`zlib` решает судьбу
`unistd.h` именно при сборке), и общий каталог означал бы, что последняя собранная
зависимость молча ломает сборку соседней оснасткой.

**Ускоренные части BoringSSL без `clang-cl` отключаются.** Они написаны в записи GNU:
переводчик MSVC такой не понимает, а `armasm64` из его же состава принимает лишь свою.
Библиотека при этом работает, но шифрует медленнее. Средство сообщает об этом при каждой
сборке; поставьте часть «Средства C++ Clang для Windows» — они включатся сами.

**Набор команд спрашивается у самой системы**, а не у переменных окружения оболочки: под
подражанием x86-64 те отвечают про подражание, и сборка молча уходила бы в x64 на машине
ARM64. Задать вручную: `set AWH_ARCH=x64`.

## Устройство

| файл | что делает |
|---|---|
| `build_third_party.bat` | окружение и перебор зависимостей |
| `third_party\_common.bat` | общая часть сборки: у зависимости остаётся лишь своё |
| `third_party\NNN_*.bat` | зависимости по порядку, `010_static` — слияние в один архив |
| `build_static_lib.bat` | присоединение зависимостей к собранной `awh.lib` |
| `build_cmake.bat` | создание `FindAWH.cmake` под место установки |

## Употребление

```bat
bat\build_third_party.bat            собрать всё, что ещё не собрано
bat\build_third_party.bat --rebuild  собрать заново, невзирая на отметки
bat\build_third_party.bat --clean    снести собранное
bat\build_third_party.bat zlib       собрать одну зависимость
```
