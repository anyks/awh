### Сборка и запуск
```bash
$ cd experience/http
$ c++ -std=c++17 -O3 -march=native -Wall -Wextra http.cpp http_demo.cpp -o http_demo
$ ./http_demo
```
> Собирается без предупреждений, чисто проходит под -fsanitize=address,undefined.

### Ключевые свойства парсера
- **Полнота HTTP/1.1**: все методы, произвольные заголовки, chunked-кодирование с `chunk-ext`, трейлеры, keep-alive, тело по `Content-Length` и «до закрытия соединения», конвейер (pipelining), корректная обработка ответов без тела (1xx/204/304/HEAD/CONNECT-туннель).
- **Производительность**: байтовый конечный автомат, `constexpr`-таблицы классов символов, bulk-копирование тела/чанков через `memcpy`; `reset()` переиспользует ёмкость буферов (без переаллокаций на keep-alive). Микро-бенчмарк в демо — **~4 млн запросов/с (~680 МБ/с)** на одном ядре.
- **Инкрементальность**: данные можно подавать любыми кусками (разрыв в любом байте) — состояние сохраняется между вызовами `execute()`.
- **Безопасность**: защита от request smuggling (запрет одновременных `Content-Length+Transfer-Encoding`, запрет различающихся `Content-Length`, требование chunked быть последним), строгая валидация символов (token/value/target), жёсткие настраиваемые лимиты (длина request-line, число/размер заголовков, **длина строки заголовка чанка**, размер тела и чанков) против DoS, ограничение предвыделения тела (`maxBodyPrealloc`) против memory-amplification, корректный `keepAlive=false` для тел «до закрытия». `execute()` строго `noexcept`: сбой аллокации даёт `Error::INTERNAL`, а не `std::terminate`.

### Семантика per-message флагов
`responseToHead` и `responseToConnect` относятся к конкретному ответу, а не к соединению, и **сбрасываются `reset()`** — выставляйте их перед каждым ответом в keep-alive/конвейере.

### 9 демонстраций в `http_demo`
GET-запрос, POST с `Content-Length`, ответ chunked+трейлеры, потоковый разбор по 1 байту, конвейер из 3 запросов, отклонение smuggling (`CONTENT_LENGTH_CONFLICT`), отклонение битого заголовка (`INVALID_HEADER_TOKEN`), ответ на HEAD (тело не читается), и микро-бенчмарк.

В ходе проверки нашёл и исправил один баг (пропуск состояния при матчинге HTTP в статус-строке ответа) — теперь все примеры отрабатывают верно.

Примечание: скомпилированные бинарники я удалил, в каталоге остались только исходники.
