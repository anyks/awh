# Проверка расхода памяти при распаковке ABC

```sh
python3 tests/codec/abc/memory.py
```

Нужны Python 3, компилятор C++17 и собранная
`third_party/lib/libdependence.a`. `CXX` задаёт путь к компилятору.
`--jobs` задаёт число параллельных компиляций (по умолчанию 4),
`--timeout` — предел времени одной команды (180 секунд),
`--output` — существующий родительский каталог для нового стенда.
`--root` позволяет проверить другое дерево исходников.

Стенд копирует исходники и зависимости в новый временный каталог, собирает их
заново с `-O2` и штатным аллокатором, без санитайзеров и готовой `libawh`.
Рабочее дерево и общие каталоги сборки не меняются. Каталог стенда сохраняется:
в нём находятся исходники, их SHA-256, мутации, журналы, `measurements.json`
и итоговый `result.json`. Код возврата — 0 при успехе, 1 при отказе.
Ошибка сборки, таймаут или изменение точек мутации означают отказ проверки.

По умолчанию проверяются все 11 методов сжатия: LZ4, LZMA, ZSTD, GZIP, ZLIB,
BZIP2, BROTLI, LIZARD, SNAPPY, DEFLATE и DENSITY. Исходное содержимое — 32 МиБ.
`--methods ZSTD LZ4` ограничивает список, `--sizes 32 128` добавляет большой вход.
Например, прежний контроль обоих размеров можно запустить так:

```sh
python3 tests/codec/abc/memory.py --methods ZSTD --sizes 32 128
```

Создание кадра и каждая распаковка выполняются отдельными процессами. Метод
проверяется в фактическом заголовке: незаметный переход к несжатому входу
означает отказ. Для каждого сочетания выполняются три повтора с `origin = 0`,
`64`, `size - 1`, `size`, `size + 1`. Правильный кадр обязан восстановить всё
содержимое; испорченный — вернуть ожидаемую причину отказа, оставить пустой
выход и не сдвинуть смещение.

Для исходного кода при `origin = 0` и `64` прирост пикового RSS должен быть
меньше 8 МиБ. Это предел данного щупа, а не обещание общего расхода памяти
компрессора: внутренние буферы и аллокатор учитываются тоже. Кадр с длиной
`size - 1` может распаковаться почти целиком до отказа и под этот порог не попадает.

Самопроверка собирает две отдельные копии `chunk.cpp`:

- Без проверки `origin == 0`: тот же `INVALID_CHUNK` приходит после распаковки.
- Без передачи предела: для `origin = 64` и `size - 1` вместо
  `COMPRESSION_FAILED` приходит `INVALID_CHUNK` от последующей сверки размера.

Для каждого алгоритма и размера медиана прироста RSS каждой целевой мутации
(`origin = 0` для первой, `64` для второй) должна превышать медиану исходной
версии более чем на половину исходного размера. Иначе прохождение нужного пути
не доказано и щуп завершается с ошибкой. По умолчанию выполняются 495 замеров;
число растёт пропорционально выбранным алгоритмам и размерам. Мутации применяются
только к копиям, по одной защите за раз.

Измерение предусмотрено для macOS и Linux: `ru_maxrss` переводится в байты
из единиц соответствующей системы. Другие системы завершаются отказом,
а не пропуском с успешным результатом. Проверено на macOS ARM64, Debian 12
(glibc, GCC 12) и Alpine 3.24 (musl, GCC 15), оба Linux-стенда x86-64.

Родительский Python удерживает дополнительные 128 МиБ до завершения всей серии,
чтобы постоянно проверять устойчивость измерения к его прежнему пику.
На Linux измерение выполняет потомок, созданный после загрузки щупа и до
инициализации AWH. Пик `ru_maxrss` после `exec` может включать память запускающего
Python: на Debian это скрывало распаковку 32 МиБ за начальным пиком около 96 МиБ.
Новый `fork` начинает учёт с текущего процесса щупа; родитель передаёт его код
завершения. Оба процесса остаются в группе, которую завершает таймаут стенда.

Проверка исправления 2 октября 2026 года: на каждом Linux-стенде пройдены
54 замера при удержании дополнительных 128 МиБ в родительском Python.
Старая версия воспроизвела незрячесть мутации, исправленная обнаружила обе
мутации и восстановила все правильные кадры. Для входа 128 МиБ прирост RSS
при отказе текущего ABC оставался менее 3 МиБ, без каждой из защит — около
259 МиБ. Код самого ABC не изменялся.

Обычный набор `unit-tests/codec` продолжает проверять функциональный договор.
Ресурсный щуп запускается отдельно, поскольку включает пересборку и мутации.

# Полный набор ABC и повреждённые кадры

```sh
python3 tests/codec/abc/validation.py
```

Запуск создаёт собственный снимок и заново собирает полный набор ABC в трёх
режимах: штатный аллокатор без санитайзеров, ASan и UBSan. Для обоих санитайзеров
аллокатор AWH отключён. В существующие проверки Editor и Storage включены
пооктетные обрывы записи в снимке носителя и настоящие частичные файловые записи
через `RLIMIT_FSIZE`, с повторным открытием и повтором фиксации.

Каждый режим дополнительно выполняет 946 сценариев `damage.cpp`: 11 алгоритмов,
с шифрованием и без него, по 43 случая. Проверяются правильный кадр, усечение
на каждом октете заголовка и в трёх местах содержимого, предельные длины,
нулевой и малый `origin`, неверная сумма, усечённый и обнулённый сжатый поток
с пересчитанной суммой. Для зашифрованного случая порча потока происходит
до корректного повторного шифрования, чтобы дойти до распаковки.

Каждый сценарий запускается отдельным процессом. Проверяются причина отказа,
очистка заранее заполненного выхода, сохранение ненулевого смещения и полное
содержимое положительного контроля. Предел RSS относится ко всему процессу,
включая подготовку входа: 512 МиБ без санитайзеров, 1 ГиБ с ними. Точные
ресурсные гарантии предела распаковки отдельно проверяет `memory.py`.

Нужны macOS или Linux, Python 3, C++17, GoogleTest/GoogleMock со статическими
библиотеками и зависимости AWH. `--gtest-root` задаёт префикс GoogleTest;
автоматически проверяются `/opt/homebrew`, `/usr` и `/usr/local`.
`--modes normal`, `--modes address` или `--modes undefined` ограничивает запуск;
`--jobs`, `--root`, `--output` имеют тот же смысл, что у ресурсного щупа.
`--timeout` задаёт предел каждой команды, по умолчанию 300 секунд. Ошибка
сборки, пропуск теста, нарушение договора или таймаут означают отказ запуска.
Журналы, XML GoogleTest, `damage.json`, SHA-256 снимка и итоговый `result.json`
сохраняются в напечатанном каталоге.

По умолчанию готовая `libdependence.a` копируется из проекта, поэтому этот запуск
сам по себе не доказывает инструментирование зависимостей. Для отдельно
пересобранных зависимостей можно передать каталог с `include` и
`lib/libdependence.a` через `--dependencies`. Режим `--modes address,undefined`
подключает оба санитайзера одновременно и подходит для зависимостей,
собранных с `-fsanitize=address,undefined`. Ассемблерные реализации не получают
проверок C/C++ санитайзеров. На macOS проверка утечек ASan отключена;
на Linux включена.

Обрыв записи в снимке моделирует сохранение записанного префикса без отката.
Он не моделирует потерю питания или переупорядочивание записей накопителем.
