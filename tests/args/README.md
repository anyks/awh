# Проверки слияния настроек args

## Пересекающиеся пути

Приоритет `DEFAULT < FILE < ENV < TEXT < CLI` действует между родителем и
потомком, а не только при точном совпадении имени. Например, сочетание
`--net.port=443` и файла `{"net":"file"}` сохраняет `net.port=443` при обоих
порядках загрузки.

Перед записью проверяются источники родительских значений и потомков.
Скаляр младшего источника освобождает место для поддерева старшего источника.
Источники удалённых значений снимаются. При превращении повторяемого объекта
в массив источники сохранённых потомков переносятся под его первое звено.
Граница сравнения — целое звено пути: `net` и `network` не конфликтуют.

Проверки в `args.cpp`:

- `IntersectingPathsRespectSourcePriority` — оба направления конфликта и оба
  порядка загрузки, значение, источник и сохранность соседа.
- `ReplacedSubtreesForgetTheirSources` — удаление источников нескольких уровней
  и запрет восстановления младшего потомка поверх старшего родителя.
- `EscapedPathsKeepTheirPriorityBoundaries` — разные имена с `/` и `~`.
- `ArrayChildrenKeepTheirPriorityAndNeighbors` — замена элемента массива без
  потери соседнего элемента, защита старшего потомка.
- `RepeatedObjectsMoveTheirChildSources` — перенос потомков вместе с объектом
  в первое звено массива повторов.

## Пустые объекты

Вложенное пустое отображение сохраняется как значение с источником и проходит
проверку строгой схемы. Пустой корневой документ не добавляет параметров и не
очищает уже собранные настройки.

- `EmptyObjectsSurviveConfigurationRoundTrips` проверяет сохранение пустоты,
  вида и источника при загрузке, а также круг выдачи и повторной загрузки через
  ABC, JSON, YAML и TOML.
- `EmptyObjectsObeyStrictSchema` проверяет отказ `UNKNOWN`, приём объявленного
  объекта и его потомка, а также допустимость пустого корневого документа.

## Отказ записи по пути

Перед изменением дерева `lay()` проверяет весь путь общими функциями разбора
ABC. Именованное поле внутри массива, недопустимый рост массива и переполнение
его длины возвращают `false` с ошибкой `INVALID_PATH`. Прежнее дерево и сведения
об источниках сохраняются; источник несуществующего значения не регистрируется.
Проверка выполняется после проверки приоритетов: запись младшего источника,
которую перекрывает старший, по-прежнему пропускается успешно.

Предел ограничивает только рост массива. Доступ к уже существующему элементу
выше текущего предела разрешён; числовые имена полей объекта индексами не
становятся. Значение предела `0` снимает ограничение роста, но не разрешает
переполнение длины массива.

Пустые имена полей отвергаются с `EMPTY_PATH` до рекурсивного слияния. В частности,
`{"":{"port":7}}` не превращается в корневой `port`, а `{"":{}}` не принимается
за пустой корневой документ. Отказ одного поля не отменяет слияние допустимых
соседних полей: атомарность относится к одной записи `lay()`, не ко всему файлу.

- `InvalidArrayPathsPreserveValuesAndSources` — отказ несовместимых имён и
  индексов, побайтовое сохранение дерева и сохранение источников.
- `FailedDescendantWritesPreserveScalarParents` — отказ на разной глубине без
  удаления скаляра или создания частичного поддерева.
- `PathValidationPreservesMappingAndArrayRules` — допустимые индексы, числовые
  имена, снятие предела и запрет переполнения длины.
- `EmptyFieldNamesAreRejectedAtEveryDepth` — пустые имена на двух уровнях,
  с включённой и выключенной строгой схемой.
- `RejectedFilePathsPreserveExistingValues` — тот же отказ при загрузке файла.

## Проверка чувствительности

2 октября 2026 года пять из первых шести новых тестов воспроизвели ошибки на
прежней реализации. Проверка массива служит дополнительной защитой от регрессии.
После исправления все семь новых тестов прошли.

В отдельных временных копиях реализации поочерёдно отключались: приоритет
родителя, приоритет потомка, освобождение скалярного родителя, очистка источников

мутаций прошла; карты линковки подтвердили использование изменённого объекта
`args.cpp.o`, а не исходного объекта из библиотеки. Рабочие исходники мутациями
не изменялись.

Для следующего исправления четыре теста отказов пути и пустого имени сначала
воспроизвели ошибки на прежней реализации. После исправления проходят все пять
добавленных проверок, включая допустимые случаи обращения по пути.

## Вид объектов и полнота массивов при загрузке

При слиянии файла новые родители создаются отображениями: их вид известен из
разбираемого дерева, поскольку массивы передаются в `lay()` целиком. Поэтому
`{"map":{"0":10,"2":20}}` сохраняет объект из двух полей, не создаёт массив
с пропущенным элементом `1` и не подчиняет числовые имена пределу роста массива.
Уже существующие контейнеры сохраняют свои правила обращения по имени или
индексу. Для CLI, текста и окружения выбор вида нового родителя по записи пути
не изменён.

Создание родителей выполняется только после проверки схемы, приоритетов и всего
пути. Отказ неизвестного листа не создаёт пустых родителей; старший скаляр не
заменяется младшим объектом. Источник записывается у значения, а новые родители
не получают вымышленного источника. Повторы собираются у листа по прежним правилам.

При чтении JSON мост сначала добавляет пустой элемент через `push()`, затем
заполняет его. Обращение по индексу здесь уже не увеличивает массив, поэтому
`abc::value_t::limit()` не обрезает запись. Это соответствует контракту ABC:
предел ограничивает индексный рост, а длину разбираемой записи задаёт её автор.
Вложенные значения заполняются на месте без копирования собранного поддерева;
проверка глубины моста сохраняется.

- `NumericFieldNamesKeepMappingKinds` — числовые имена на нескольких уровнях,
  ограждение имени родителя, пустой объект, замена скаляра и источники; форматы
  ABC, JSON, YAML и TOML.
- `NumericMappingsRespectSchemaPriorityAndRepetition` — строгая схема листа,
  отсутствие частичного дерева при отказе, приоритет родителя и листа, повторы.
- `ConfigurationArraysAreNotTruncatedByTheGrowthLimit` — полная загрузка
  вложенного JSON-массива в args и последующее изменение существующего элемента.
- `CodecBridge.JSONArraysIgnoreTheIndexGrowthLimit` — сравнение полных деревьев
  после загрузки пустых, плоских и вложенных массивов с пределом роста `0` и `2`.

Все четыре новые проверки и усиленная `PathValidationPreservesMappingAndArrayRules`
воспроизвели дефекты до исправления. Последняя теперь загружает объект с числовыми
именами непосредственно, без предварительного создания пустого объекта.

После этого исправления локально прошли args — 88/88 и codec — 2567/2567.
Повторный прогон args на тех же девяти начальных значениях генератора прошёл
27 000 итераций без ошибок. Ворошитель bridge прошёл ещё 9000 итераций: по 3000
для `1`, `42`, `31337` при глубине генерации `3`, без ошибок.

## Нулевой байт в имени и переносимость теста окружения

Вложенные пути собираются операциями `std::string`, сохраняющими полную длину
имени. Форматирование через `%s` обрезало имя по нулевому байту: поле
`parent.a\u0000b` превращалось в `parent.a`, могло смешаться с его значением и
ошибочно пройти строгую схему короткого имени. Имена с нулевым байтом принимаются
по тем же правилам, что и остальные имена, без изменения их байтов.

- `EmbeddedNullNamesSurviveConfigurationRoundTrips` проверяет имена листа и
  родителя, несколько уровней и отдельного соседа с коротким именем; сравнивает
  полные деревья при загрузке, выдаче и повторной загрузке через JSON и ABC.
- `EmbeddedNullNamesCannotImpersonateSchemaParameters` проверяет отказ `UNKNOWN`
  при объявленном коротком имени и приём отдельно объявленного полного имени.
- `EmbeddedNullNamesKeepIndependentPriorities` проверяет сохранность значения
  CLI по полному имени и независимую загрузку короткого имени из файла.

Все три проверки воспроизвели ошибки до изменения сборки пути.

В `EnvironmentNamesAreEscapedForTheStorageAxis` вызовы `setenv` и `unsetenv`
заменены существующими помощниками `setupEnv` и `clearEnv`. Они используют
`_putenv_s` в Windows и прежние POSIX-вызовы на остальных платформах.

Проверка после исправления 2 октября 2026 года: args — 91/91, codec — 2574/2574.
На стенде MinGW64 с GCC 16.1 прошла синтаксическая компиляция всех девяти файлов
реализации и тестов args/bridge, а также подключение `windows.h` до и после
заголовков модулей. Использованы C++17, `WIN32_LEAN_AND_MEAN`, `NOMINMAX` и
`-fsyntax-only`. Хеши двух обновлённых файлов на стенде совпали с локальными.
Линковка и запуск наборов тестов на Windows этим прогоном не проверялись.

## Проверка чувствительности и сочетаний имён

Дополнительный проход 2 октября 2026 года подтвердил чувствительность последних
регрессий. В отдельных временных копиях исходников проверены четыре подмены:

- Возврат сборки вложенного пути через `%s`: падают все три проверки имён с
  нулевым байтом.
- Отключение создания отображения перед записью числового имени: падают обе
  проверки сохранения числовых имён и их взаимодействия со схемой и приоритетами.
- Отключение предварительной проверки пути: падает проверка сохранности
  скалярных родителей при отказе записи потомка.
- Отключение добавления элемента перед заполнением массива JSON: падает
  `CodecBridge.JSONArraysIgnoreTheIndexGrowthLimit`.

Соответствующие контрольные сборки прошли все семь проверок. Карты связывания
подтвердили использование временных объектных файлов вместо одноимённых частей
архива; исходники рабочего дерева при подменах не менялись.

Отдельная временная программа проверила 972 сочетания: по 18 имён родителя и
потомка в ABC, JSON и YAML. Включены числовые имена, тильды, косые черты,
точки, управляющие знаки, нулевые байты и кириллица. Проверены совпадение дерева
с непосредственным чтением кодеком, строгая схема с разделителем `|` и сохранение
приоритета CLI при последующей загрузке файла. Все сочетания прошли.

После этих проверок локально повторно прошли args — 91/91 и отдельно Bridge —
61/61. Новых исправлений реализации этот проход не потребовал.

## Запуск

Сборка из корня проекта:

```sh
ninja -C build awh_UNITTEST_args awh_UNITTEST_codec
```

Наборы запускаются из `build`:

```sh
./unit-tests/args
./unit-tests/codec
```

Для сборки с покрытием независимым прогонам следует задавать отдельные каталоги
`GCOV_PREFIX`, чтобы не смешивать их счётчики.

## Оформление

Эталон оформления — `src/net/backend/bsd/kqueue.cpp`. В модуле точечно исправлены
пробелы перед скобками блоков `if` и `if constexpr`, оформление объявлений тестов
и противоречащие друг другу комментарии о корневом узле XML. Эти правки не меняют
поведение разбора и проверок. Массовое автоформатирование не применялось.
У `else if` и `else if constexpr` пробел перед открывающей скобкой сохранён
по образцу ветвей `else if` в эталоне.
