# Что перенять из общего кода

Сводка для того, кто ведёт бэкенд MS Windows. Здесь собрано то, что изменилось
в общем коде и в эталонных бэкендах (`bsd/kqueue.cpp`, `gnu/epoll.cpp`) и что
касается Windows: либо ломает сборку прямо сейчас, либо пригодится, когда работа
дойдёт до сетевого движка.

Состояние на **07.08.2026**, срез `a1533f5d`.

---

## 1. Ломает сборку прямо сейчас

### `switchOption` получил пятый довод

`awh::eth::Socket::switchOption` теперь принимает протокол сокета:

```cpp
bool switchOption(
    const net::socket_t sock,
    const event::family_t family,
    const net::socket_mode_t mode,
    const uint16_t option,
    const event::protocol_t proto = event::protocol_t::NONE
) const noexcept;
```

В [`eth.cpp:1026`](eth.cpp#L1026) определение осталось четырёхдоводным — это
расхождение с заголовком [`include/net/eth/socket.hpp:265`](../../../../include/net/eth/socket.hpp#L265),
и оно даёт ошибку прямо при разборе:
`out-of-line definition of 'switchOption' does not match any declaration`.

Правка на стороне Windows — дописать довод в определение-заглушку:

```cpp
bool awh::eth::Socket::switchOption([[maybe_unused]] const net::socket_t sock, [[maybe_unused]] const event::family_t family, [[maybe_unused]] const net::socket_mode_t mode, [[maybe_unused]] const uint16_t option, [[maybe_unused]] const event::protocol_t proto) const noexcept {
```

**Зачем довод заведён.** При установке `TCP_NODELAY` движок прежде спрашивал у
ядра протокол сокета (`SO_PROTOCOL`), хотя сам же этот сокет и заводил, — лишнее
обращение к ядру на каждое подключение. Теперь вызывающий вправе назвать протокол,
и разыскивается он только при `NONE`. Довод со значением по умолчанию: мест вызова
много, и обязать все их назвать протокол значило бы править то, чему он безразличен.

Когда бэкенд Windows дойдёт до настоящей работы с опциями, тот же приём здесь
уместен — `WSAIoctl`/`setsockopt` за протоколом ходить незачем, он известен из
`issue()`.

### Больше расхождений нет

Сверка проведена сличением всех определений `win/eth.cpp` и `win/iocp.cpp` с
объявлениями в `include/net/eth/{socket,iface}.hpp` и `include/net/io.hpp`.
Кроме `switchOption` расхождений **нет**: четвёрка методов MTU
(`Interface::mtu` ×2, `Interface::configure` ×2) уже отвечает заголовкам.

## 2. Два дефекта, общих для всех систем

Оба найдены при переносе на Linux, оба исправлены в `kqueue.cpp` и `epoll.cpp`.
Ни один не Linux-специфичен — Linux их лишь обнажил. Второй лежит в общем коде и
Windows достаётся уже исправленным, первый придётся не повторить самому.

### Свой адрес в поле удалённой стороны SCTP

У слушающего узла SCTP в `SCTP_PEER_ADDR_PARAMS.spp_address` подставлялся **свой**
адрес. По RFC 6458 это поле — адрес **удалённой** стороны. FreeBSD прощает и отдаёт
параметры конечной точки, Linux ищет по нему путь ассоциации и отвечает `EINVAL`,
подвешивая приём. Исправлено одинаково в обоих движках: у слушающего узла адрес не
передаётся вовсе.

Windows SCTP не поддерживает, так что перенимать нечего. Записано ради общего
правила: **поле «адрес» в опциях SCTP всегда про удалённую сторону**, и
снисходительность одной системы не делает обращение верным.

### `Unit::stop()` терял просьбу, поступившую до запуска

`awh::unit::Unit::stop()`, вызванный **прежде** `start()`, пропадал впустую, и
следующий `start()` уходил в ожидание навсегда. Случай не выдуманный: обращение
вправе отказать сразу, из той же функции, которой начато. Исправлено отметкой
`_stopped` в [`src/units/unit.cpp`](../../../units/unit.cpp).

Это общий код — под Windows он тот же. Отдельно к сведению кластера: порядок
«остановить, потом запустить» теперь отрабатывает правильно.

## 3. Чему учит перенос на epoll

Три дефекта переноса, вскрытые не чтением кода, а **счётом обращений к ядру**.
Все три — про readiness-модель, но два из трёх один в один повторяются в IOCP,
и повторятся тем больнее, что IOCP дороже за обращение.

### Учёт подписок переживал закрытие дескриптора

`close()` в Linux сам снимает подписки epoll, но внутренний учёт движка об этом не
узнавал. Дальше по тому же номеру дескриптора заводился новый сокет, и движок считал
его уже подписанным. Ошибок было 8389 за прогон.

Отличить нового владельца **по адресу узла нельзя** — распределитель выдаёт тот же
адрес; я это проверил и откатил. Достоверный признак один: само закрытие. Отсюда
обёртка `::kernel::close(sock)`, через которую проходят все 59 мест закрытия.

**Для IOCP это то же самое, только строже.** Связь дескриптора с портом завершения
не разрывается ничем, кроме закрытия, и заново связать уже связанный дескриптор
нельзя (`ERROR_INVALID_PARAMETER`). Так что учёт «этот сокет связан с портом»
обязан забываться ровно в момент закрытия, и единая обёртка закрытия здесь не
удобство, а условие правильности.

### Каждая правка подписки шла в ядро своим обращением

Перенос вышел дословным с kqueue, где правки копятся в списке изменений и уходят в
ядро одним `kevent`. У epoll такого списка нет, и получилось по `epoll_ctl` на
правку — шесть на подключение.

Теперь правки копятся в учёте, а перед самым ожиданием согласуются пакетом: одно
обращение на дескриптор. Порядок в опросе стал `commit → sweep → flush → ожидание`.
Обращений на подключение 6 → 3.

**IOCP не имеет ни списка изменений, ни `epoll_ctl`** — там подписки как таковой
нет, есть выданные операции. Но накопление с отложенным согласованием остаётся
верным приёмом: несколько `WSARecv`/`WSASend`, выданных одним заходом, лучше
чередования «выдал — подождал».

### Лишнее чтение до `EAGAIN`

У kqueue вместе с готовностью приходит объявленный объём, у epoll его нет, и
перенос читал до отказа — лишнее обращение на каждый обмен. Решается коротким
чтением: при **уровневой** подписке недобор до размера буфера значит, что данные
кончились, а придут новые — ядро сообщит снова.

**Опасность, которая перенесётся:** для дейтаграмм и `SEQPACKET` это рассуждение
**неверно** — короткое сообщение не значит пустую очередь, там может лежать ещё
одно. В `epoll.cpp` это разведено доводом `size` метода `Watchdog::consume`:
на потоковых путях он передаётся, для SCTP явно обнуляется.

В IOCP уведомление приходит с числом переданных байт, как у kqueue, так что прямого
переноса не требуется — но правило «объём сообщения не говорит ничего о длине
очереди» касается любой модели.

## 4. Чем мерить

Счётчик обращений к ядру заведён и работает на macOS и Linux:
[`tools/benchmark/syscount`](../../../../tools/benchmark/syscount).
Замедление 16 % против семнадцатикратного у `strace`, так что мерить можно на
живой нагрузке, а не на игрушечной.

Способ подмены разный: macOS — `__DATA,__interpose` (подлинная функция достижима по
имени), Linux — `LD_PRELOAD` с разысканием подлинной через `dlsym(RTLD_NEXT, …)`.
**Под Windows не заведён.** Родственный приём там — подмена таблицы импорта (IAT)
или Detours; работа не на вечер, и браться за неё имеет смысл не раньше, чем IOCP
начнёт передавать данные.

Ради чего: именно счётчик, а не чтение кода, вскрыл все три дефекта выше.
Три раза подряд догадка «где может быть медленно» оказывалась мимо, а счёт
обращений указывал на место сразу.
